Noah 2.0 · Companion to “The Mastery Loop”

The Mastery Loop, drawn

Every term defined in one line, the router you can poke, what each activity does to the score, and one student driven through a whole topic by it. Fractions, 3 objectives.

§ 00The words, first

Every term this document uses, in one line each. If a sentence later on stops making sense, the word you are missing is on this page.

Here is the whole idea in four sentences.

A topic is made of two or three learning objectives. Each objective carries one number, 0–100, saying how well the student has it — all of those numbers together are the scorecard.

At the start of a session the router reads that scorecard, runs down a fixed list of rules, and picks the single thing that helps this student most right now — a test, a practice set, or a class.

The student does it, the numbers move, and next session the router reads them again. It stops when every objective is signed off.

The things being measured

TermIn plain language
Learning objectiveLO One specific skill inside a topic. In Fractions: "compare two fractions", "add fractions with unlike denominators". The smallest thing this system tracks. Real curriculum data says a topic carries 2–3 of them, not six.
Topic The unit a student works through — Fractions, Decimals. It has its own score too, but that score is a summary of its objectives, not a separate measurement.
Round One session. The router decides once per round. "4 rounds stalled" means four sessions in a row where nothing improved.
Attempt What one activity scored on one objective, 0–100. Points earned ÷ points possible. It is the new evidence, not the new score — the score only moves part of the way toward it.

The record

TermIn plain language
Scorecard One row per objective, plus one row for the topic. This is the only thing that survives between sessions. Everything the router knows, it reads from here.
Score The 0–100 number on an objective. Not an average of every question ever answered — it leans toward recent work on purpose, so a student who started at 60 and is now at 85 reads as 85, not 73.
Confidence A separate 0–1 number answering "how much do we trust that score?" A score of 82 built on three questions and a score of 82 built on twenty are not the same claim. Below the bar the platform returns no score at all rather than a guess. It rises with more questions, more question types, and more difficulty bands — not just more questions. This already exists on the platform.
Lockedconfidence locked Shorthand for "we have enough evidence to act on this score". Several rules refuse to fire until an objective is locked, so the router never makes a big decision on thin data.
LO state A label the router works out from the score and confidence — it is never stored. Six of them: untested (no evidence yet), working (in progress), ready (looks masterable, worth testing properly), needs_help (below 60, teach it), blocked (failed the check twice, a human is needed), signed_off (done).
Signed offcertified An objective is finished and will not come back. Only one activity is allowed to do this — the LO check. Nothing else can end an objective, no matter how high the score gets.

The decision

TermIn plain language
Router The piece that decides what the student gets next. It reads the scorecard and outputs exactly one activity. It has no memory of its own and no schedule — ask it the same question with the same scorecard and it always answers the same way.
Rule ladderR0–R7 The router's logic: eight rules in a fixed order, read top to bottom, first match wins, stop. No scoring of options, no weighting, no tie-breaks — which is why you can read the ladder and predict exactly what a student will be given. The order is the design: safety first, then certification, then teaching, then testing.
Activity The thing the router hands back — a topic survey, an LO check, homework, practice, or a class. One per round.
Sequencer The layer above this loop that chooses which topic a student works on. The loop takes the topic as given and never argues with it. Placement, grade tests and multi-topic tests feed the sequencer, not the loop.

The activities

TermIn plain language
Topic survey The first thing a student gets in a new topic, before any teaching. It touches every objective in the topic, at least 3 questions each, and its whole job is to fill in the scorecard so the router has something to read. It is a real test and it moves scores — but it fires before teaching, so it is not allowed to sign anything off. today: the topic test
LO check A short, strict test on one objective only — 5 questions, timed, no hints, and every question is one the student has never seen. It is the exam at the end of an objective, and the only activity allowed to sign one off. The router only calls it when an objective already looks ready; it is confirmation, not exploration. today: the topic test, narrowed
Homework The workhorse — about 12 questions across the topic, unhinted, untimed. It is a real measurement and it moves scores, just at half weight because it is low-pressure. What changes is which objectives it picks: driven by the scorecard instead of an even spread.
Practice 5 questions with hints and unlimited retries. Because the format guarantees a correct answer eventually, it cannot measure anything — so it moves no score at all. It teaches. That is a change: practice writes a score today.
Class A request into the mentor tool — get a human to teach this. Produces no questions and moves no numbers. The router's answer when more testing would be pointless.
Placement 20 questions across a whole grade, taken once. Its job is choosing where to start. It seeds the topic row with a cautious first guess and is thrown away the moment that topic's survey runs. It writes nothing per objective — 20 questions across a grade is far too thin for that.

The maths

TermIn plain language
Score weightw How much an activity's result is believed. Survey and check 1.0, homework 0.5, practice 0. Answers "how honest is this measurement?"
Learning ratek(n) How far the score moves toward the new evidence. Big early, smaller later — the first result on a fresh objective should move it a lot; the tenth should not. n is how many measured rounds that objective already has. It has a floor so that a long-standing score can still change when a student genuinely improves.
Difficulty modifierd under review An adjustment for how hard the questions were. Careful: difficulty is already inside the attempt score, because a hard question is worth 4 points and an easy one 2. Applying it twice quietly inflates hard-question gains. Whether d should exist at all is the one number still open — see §02.
Fresh-only Every question is one this student has never been served, in any flow. The LO check demands it — you cannot certify someone on questions they have already seen the answer to. The platform already tracks this across flows.
Golden LO rule An existing platform rule: an objective is only included in a test if it can get at least 3 questions. Fewer than that and it is silently dropped — which matters, because a short survey config can leave objectives untested without saying so.

The one distinction people keep tripping over

Topic survey and LO check are the same engine. Today's topic test does both jobs at once: it sweeps every objective, and it is also what decides whether a student is done. Those are different jobs and they want different shapes.

The survey is wide and early — every objective, before teaching, to find out where the student stands. The check is narrow and late — one objective, fresh questions, after teaching, to close it out. Same question bank, same scorer, two blueprints.

The order is the design

Safety above everything — a student who is drowning or looping never gets handed another worksheet.
Certification above teaching — move R5 below R7 and sign-off starves.
Teaching above measuring — an LO at 47 needs teaching, not another test.
R6's second clause is load-bearing. Practice writes no score, so without “measured since last practice” the router prescribes practice, sees no change, and prescribes it again forever. And it fails silently — the student can be improving the whole time, and because practice writes no score there is nothing for the router or the mentor to see.

Practice at weight 0 is a change, not the status quo — it writes to progress_student_lo today. See §02.

What each one does to the score

Every activity gets judged on three separate questions, and the answers do not have to match: how much does its result count, does it make us more sure, and is it allowed to declare an objective finished. The temptation is to collapse them into one "how good is this test" rating. Don't — the topic survey scores as cleanly as a check but must never end a topic, and that is only expressible with three dials.

The update rule

Read it as one sentence: move the score part of the way toward the new result, and how far depends on how much we trust it. Nothing is ever replaced outright, and nothing is a plain average — a lifetime average would strand a student who started at 60 and finished at 85 on a permanent 73.

score' = score + w · k(n) · d · (attempt − score)

  attempt   this activity's result on THIS objective, 0–100
            points earned ÷ points possible, where a question is worth
            easy 2 · medium 3 · hard 4, × correct 1.0 · partial 0 · incorrect 0
            partial earns nothing — half an answer is not half an objective
            a correct-but-slow answer already takes a 0.9× hit in the live scorer

  w         how much this activity's word is worth
            survey/check 1.0 · homework 0.5 · practice 0
  k(n)      how far the score moves toward it
            0.80 / (1 + n/6), floored at 0.15
            n = prior measured rounds. Early rounds move the score a lot, later ones less —
            the floor is what stops it freezing once a student has history.
  d         difficulty modifier  applied to the GAIN, never to the attempt score

The trap: difficulty counted twice

The live scorer already weights by band — 2 / 3 / 4 points. Because attempt is earned over possible, difficulty cancels out of it. Multiplying the attempt score by a difficulty modifier again would silently inflate hard-question gains. It belongs on the gain term, and asymmetrically:

Bandd, score risingd, score fallingReads as
Easy0.501.00Cheap to pass, expensive to fail
Medium0.700.85Roughly symmetric
Hard1.000.60The only route to a high score; failing one is forgivable

One round, worked

LO3 sits at 51 with 2 prior measured rounds. A homework round serves it four questions: easy correct, medium correct, medium partial, hard wrong. The partial earns nothing.

  points     easy 2×1.0 + med 3×1.0 + med 3×0 + hard 4×0     =  5.0
  possible   2 + 3 + 3 + 4                                   = 12.0
  attempt    5.0 / 12.0                                    = 42

  w          0.5                    homework
  k(2)       0.80 / (1 + 2/6)       = 0.60
  d          0.85                   medium-weighted set, score FALLING

  score' = 51 + 0.5 × 0.60 × 0.85 × (42 − 51) = 51 − 2.3 = 48.7

Note the sign. With partial credit the same round scored 54 and nudged the objective up by 0.6; at partial 0 it scores 42 and pulls it down 2.3 — and the falling-side difficulty modifier is harsher, which compounds it. Had the round come back clean at 85 the move would be 0.5 × 0.60 × 0.70 × 34 = +7.1. The score chases the evidence at a rate set by how much history it already has.

Two things to settle before this is built

Per activity, not per question. attempt is one activity's result on one objective — apply it per question and k is far too hot, swinging an LO several points on a single easy item. The plan does not say this explicitly; it should.

Three things this run shows

Practice is always followed by measurement. Sessions 3 and 5 are practice; R6 will not fire twice in a row, because practice writes no score and the router would otherwise loop on it forever.
Certification does not wait. Session 7 checks one objective while the other two are still mid-flight.
The topic ends at 84. Everything certified, nothing left to prescribe — and an 85 topic-score gate would trap this student permanently.

The confidence lock is still a placeholder

The platform's live confidence formula saturates at four questions — one question already clears it, and five records read the same as thirty. It cannot gate a multi-week loop as-is. This run assumes a re-capped version. See §03 of the main doc.
